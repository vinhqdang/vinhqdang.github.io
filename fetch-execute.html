A working Von Neumann computer you can take apart. Step through the cycle one register transfer at a time, change the program in memory, and see what the Control Unit, ALU and registers do. Then break it on purpose.

This page supports British University Vietnam students in the module Introduction to Computing Science (2024–2027 and onwards). It accompanies the Week 8 “Systems” lecture.

      Instruction set of this machine

      Each instruction is one 8-bit word: the top 4 bits are the opcode, the bottom 4 bits are the operand (usually an address). Cells holding 0 decode as HLT. Opcodes 11–15 do not exist.

      Things to try

      1. Predict, then check. Load the lecture example. Before each instruction, write down what ACC and memory will hold afterwards.
      2. Change the operands. Edit ADD 5 to SUB 5 in the lecture example. What is 101 − 143 in 8 bits?
      3. Execute data. Set Start PC to 4 so the CPU fetches the number 101. Which instruction is 0110 0101? Remember: the “As code” column shows how the CPU would read every data cell.
      4. Design a program. Use Blank memory to compute (a + b) − c, or to double a number, and print the answer.
      5. Diagnose the five bugs in the Bugs to diagnose group. Run each, find what went wrong from the Bug watch and the trace, fix it by editing memory, and run it again.
      6. Count memory accesses. How many trips to memory does the multiplication program make? Why would a separate memory for instructions and data (the Harvard model) help?
      7. Break it your way. Press 🎲 Random memory and Run. Is a random program more likely to halt, fault or loop forever? Why?

      Teaching machine: 16 cells of 8 bits with 4-bit addresses, so addresses wrap at 16 and numbers at 256. Real CPUs use 32- or 64-bit registers and addresses, but follow the same cycle.
